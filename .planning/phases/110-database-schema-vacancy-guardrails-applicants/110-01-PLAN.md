# Phase 110: Database Schema & Vacancy Guardrails for Applicants - Plan

**Phase:** 110
**Goal:** Add `is_resident` and `notes` to SQLite `tenants` table with automatic idempotent migrations; guard occupancy and tenure calculations across tree, cards, profile, and search; ensure auto-reallocation ignores non-residing applicants for general document matching.
**Requirements:** DB-01, DB-02, VCN-01, VCN-02

---

## Tasks

### Task 1: Schema Migrations & Data Models (DB-01, DB-02)
- In `src/HousingApplication.Web/Data/DatabaseInitializer.cs`:
  - Update `SchemaSql` to declare `is_resident INTEGER NOT NULL DEFAULT 1` and `notes TEXT` on `tenants` table.
  - Add index `idx_tenants_resident ON tenants(is_resident)`.
  - Add idempotent migration statements for existing databases in both `InitializeSchema` and `InitializeSchemaAsync`:
    - `ALTER TABLE tenants ADD COLUMN is_resident INTEGER NOT NULL DEFAULT 1;`
    - `ALTER TABLE tenants ADD COLUMN notes TEXT;`
- In `src/HousingApplication.Web/Models/Tenant.cs`:
  - Add `public int IsResident { get; set; } = 1;`
  - Add `public string? Notes { get; set; }`
- In `src/HousingApplication.Web/Models/DTOs.cs`:
  - In `TenantDto`: add `IsResident` (default 1) and `Notes`.
  - In `HouseTenantProfileDto`: add `IsResident` (default 1) and `Notes`.
  - In `TreeTenantDto`: add `IsResident` (default 1).
  - In `SearchResultDto`: add `IsResident`.

### Task 2: Repository Queries & Vacancy Guardrails (VCN-01, VCN-02)
- In `src/HousingApplication.Web/Data/FileOrganizerRepository.cs`:
  - `EnsureSchemaAsync`: ensure migration for `is_resident` and `notes` is invoked.
  - `GetTreeAsync`:
    - Select `is_resident AS IsResident, notes AS Notes`.
    - Restrict `activeTenant` detection to `t.IsResident == 1`.
    - Fallback subtitle for vacant house only considers residents (`t.IsResident == 1`).
    - Populate `IsResident` on `TreeTenantDto`.
  - `GetHouseCardsAsync`:
    - Select `is_resident AS IsResident, notes AS Notes`.
    - Restrict `activeTenant` detection to `t.IsResident == 1`.
    - If house has no active resident, only check `residentTenants.Count > 0` for past resident subtitle; if only applicants exist, house is `grey` with null subtitle.
  - `GetHouseProfileAsync`:
    - Select `is_resident AS IsResident, notes AS Notes`.
    - Restrict `activeTenant` to `t.IsResident == 1`.
    - Map `IsResident` and `Notes` into `HouseTenantProfileDto`.
  - `GetTenantsAsync`:
    - Select `is_resident AS IsResident, notes AS Notes`.
    - Order by `is_resident DESC` first so actual residents appear before applicants.
  - `SearchAsync`:
    - Add `AND is_resident = 1` to `CurrentTenant` subquery in houses search.
    - In tenant search, if `t.IsResident == 0`, set `IsCurrent = false` and `DurationCategory = null`, and map `IsResident = t.IsResident`.
    - In document search, map `IsResident` if joined.
  - `AddTenantAsync`:
    - Add optional parameters `int isResident = 1, string? notes = null` and include in `INSERT INTO tenants`.
  - `BulkUpdateTenantsAsync`:
    - Read `is_resident AS IsResident, notes AS Notes`.
    - Include `is_resident` and `notes` in `INSERT INTO tenants` and `UPDATE tenants`.
    - In reallocation: filter `residentTenants = updatedTenants.Where(ut => ut.IsResident == 1).ToList()`.
    - Only assign documents in date-window or default fallback to `residentTenants`.
- In `src/HousingApplication.Web/Data/IFileOrganizerRepository.cs`:
  - Update `AddTenantAsync` method signature.
- In `src/HousingApplication.Web/Program.cs`:
  - In document ingestion fallback tenant resolution, prioritize `tenants.FirstOrDefault(t => t.IsResident == 1)`.
