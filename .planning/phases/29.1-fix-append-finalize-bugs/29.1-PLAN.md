# Phase 29.1 — Plan 01: Fix Append-Mode Finalize Bugs

**Phase:** 29.1 — Fix Append-Mode Finalize Bugs
**Created:** 2026-07-25
**Status:** Ready

## Summary

Fix three critical bugs in the append-mode finalize flow that cause duplicate house directories, unnecessary `_raw_append.pdf` intermediate files, and wrong target directory resolution. Add tests to prevent regression.

## Agreed Solution (User-Approved)

1. Compress only the **new incoming pages** into a temp PDF
2. Open the **existing** `_finalized.pdf` with PyMuPDF
3. Insert the new compressed pages at the end
4. Rebuild the TOC from `_3_routed_and_finalized.json` (just text bookmarks, no image re-processing)
5. Save the updated `_finalized.pdf` directly — **no re-compression of existing pages**
6. Delete `_raw_append.pdf` logic entirely

## Tasks

### Task 1: Prevent house directory rename in append mode

**File:** `src/timeline/core.py`
**Lines:** 119-164 (`ensure_target_directories`)

**What to do:**
- Add an `append_mode: bool = False` parameter to `ensure_target_directories()`
- When `append_mode=True`, skip the rename logic entirely — just ensure the target directories exist within the **existing** `house_dir` without trying to rename it
- The `organize()` method (line 285) should also accept and pass through `append_mode`
- In append mode, `organize()` should NOT derive `target_dir` from `Path(source_pdf).parent` (line 313) — instead accept an explicit `house_dir` parameter

**Why:** The current code tries to rename `C:\Users\Emad\AppData\Local\Temp` to `D:\Areas\Safra D\502 - ...` which fails with WinError 17 (cross-drive). The fallback creates a brand new empty directory.

**Verification:**
```
- organize() in append mode never calls Path.rename()
- No new directories created when house_dir already exists
- Individual document PDFs still placed in correct tenant subfolders
```

### Task 2: Remove `_raw_append.pdf` logic from `finalize()`

**File:** `src/watcher/orchestrator.py`
**Lines:** 402-555 (second half of `finalize()`)

**What to do:**

Replace the current flow:
```
raw_append_pdf → append pages → compress entire thing → overwrite _finalized.pdf
```

With:
```
1. Compress the new pages (from the OK'd PDF) using compress_pdf into a temp file
2. Open the existing _finalized.pdf with fitz
3. Insert the compressed new pages at the end using insert_pdf
4. Rebuild TOC from _3_routed_and_finalized.json (all docs, not just new)
5. Save _finalized.pdf directly (no whole-file recompression)
6. Delete the temp compressed file
```

**Specific changes:**
- Remove lines 407-431 (raw_append_pdf creation and appending)
- Remove lines 557-589 (rebuild finalized from raw_append)
- Replace with new logic that:
  - Calls `compress_pdf(ok_pdf_path, temp_compressed_path)`
  - Opens existing `_finalized.pdf` with `fitz.open()`
  - Calls `insert_pdf()` to append new compressed pages
  - Reads `_3_routed_and_finalized.json` to build full TOC
  - Saves directly to `_finalized.pdf`
- Remove any reference to `_raw_append.pdf` in the codebase

**Why:** The `_raw_append.pdf` defeats the purpose of compression and causes recompression of already-compressed pages on every append.

**Verification:**
```
- No _raw_append.pdf exists in .source_files/ after finalize
- _finalized.pdf grows by approximately the size of the new compressed pages
- Existing pages in _finalized.pdf are not re-compressed (byte-identical)
- TOC has correct bookmarks for all documents (old + new)
```

### Task 3: Fix house_dir resolution — resolve once, never change

**File:** `src/watcher/orchestrator.py`
**Lines:** 327-338 (house_dir first resolution) and 561-567 (re-resolution after organize)

**What to do:**
- Remove the re-resolution block at lines 561-567 entirely
- The `house_dir` resolved at lines 327-338 must be treated as final for the entire `finalize()` call
- Pass `house_dir` explicitly to `run_generation_pass()` and ensure `organize()` uses it (via the `append_mode` parameter from Task 1)
- Update `run_generation_pass()` in `src/pipeline/runner.py` to accept an optional `fixed_house_dir` parameter. When provided, pass it through to `organize()` and skip any directory rename logic

**Why:** After `organize()` potentially creates a new directory (Bug 1), re-scanning `area_dir` picks up the wrong directory. Even with Bug 1 fixed, re-resolution is fragile.

**Verification:**
```
- finalize() resolves house_dir exactly once
- All file operations use the same house_dir throughout
- run_generation_pass() respects fixed_house_dir when provided
```

### Task 4: Add regression tests

**File:** `tests/test_finalize_append.py` (new file)

**What to do:**

Create the following test cases:

1. **`test_finalize_uses_existing_house_dir`**
   - Setup: Create a house dir `502 - OldTenant` with a `_finalized.pdf` and `.source_files/` containing `_tenants.yaml` and JSON files
   - Action: Run `finalize()` with a proposed PDF whose name resolves to `502 - NewTenant`
   - Assert: No `502 - NewTenant` directory is created. Documents are placed in the existing `502 - OldTenant` directory

2. **`test_finalize_no_raw_append_created`**
   - Setup: Same as above
   - Action: Run `finalize()`
   - Assert: No `_raw_append.pdf` exists anywhere in the house dir or `.source_files/`

3. **`test_finalize_appends_to_existing_finalized_pdf`**
   - Setup: Create a house dir with a `_finalized.pdf` containing 5 pages
   - Action: Finalize a 3-page document
   - Assert: `_finalized.pdf` now has 8 pages
   - Assert: The first 5 pages are byte-identical to the originals (no re-compression)

4. **`test_finalize_toc_includes_all_documents`**
   - Setup: Create a house dir with existing `_finalized.pdf` and JSON files tracking 3 documents
   - Action: Finalize 2 new documents
   - Assert: `_finalized.pdf` TOC has 5 bookmark entries

5. **`test_ensure_target_dirs_append_mode_no_rename`**
   - Setup: Create `target_dir` on one path and `house_dir` on another
   - Action: Call `ensure_target_directories(append_mode=True)`
   - Assert: `target_dir` was NOT renamed. `house_dir` directories exist.

**Testing approach:** Use `tmp_path` fixture, mock the LLM client, create minimal PDFs with `fitz.open()`, and mock `compress_pdf` to return the input unchanged.

**Verification:**
```
- All 5 tests pass
- pytest runs clean with no warnings related to these tests
```
