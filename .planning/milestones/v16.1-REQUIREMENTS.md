# Requirements: Milestone v16.1 Document-Anchored Tenancy Dates & Minimalist Register

## Milestone v16.1 Goals

Anchor tenant and applicant start dates directly to the date of their earliest document in the archive (`MIN(primary_date)`), eliminating manual start date entry and timeline conflicts. For brand-new entities with zero documents, display "Auto (on first upload)" until their first document is ingested. Retain user control over the end date (Present vs. specific vacate/closing date). In the House Profile, streamline the tenant selection area into a clean, minimalist layout: all residents at the top, a single divider line, and all applicants at the bottom, using simple one-word labels.

## Requirements

### Document-Anchored Tenancy Dates (DAT)
- [x] **DAT-01**: In the backend (`FileOrganizerRepository.cs` and `Program.cs`), resolve/derive the effective start date of each tenant/applicant from their earliest document (`MIN(primary_date)` where `tenant_id = t.id AND is_timeline_visible = 1`), syncing `start_date` so that the archive timeline is 100% self-consistent.
- [x] **DAT-02**: Handle the zero-document edge case: when a brand-new tenant or applicant has zero documents, their start date displays as "Auto (on first upload)" (or empty placeholder), and automatically snaps to the document's date upon the very first document upload.
- [x] **DAT-03**: Preserve user-decided end dates: the user controls whether a tenant is `Present` (currently active) or specifies a vacate/closing `end_date`. Ingestion conflict validation evaluates against this user-decided end date for residents.

### Minimalist Register Layout (REG)
- [x] **REG-01**: Streamline the House Profile tenant register in `house-profile.js`:
  - Display all resident tenants at the top under a simple header: `المستأجرون` (Tenants).
  - Insert exactly 1 clean divider line (`<hr>` or subtle border divider) separating residents from applicants.
  - Display all applicants at the bottom under a simple header: `المتقدمون` (Applicants).
  - Eliminate wordy boilerplate or redundant subtitle descriptions.
- [x] **REG-02**: In the House Settings modal (`tenant-manager.js` and `index.html`):
  - Start Date input displays the auto-anchored date (with placeholder `Auto (on first upload)` if empty).
  * End Date and Present checkbox remain interactive and user-decided.
  * Preserves 12-column grid and two-way Resident $\leftrightarrow$ Applicant switching.

### Verification & Testing (VER)
- [x] **VER-01**: Add unit and integration tests in `HousingApplication.Tests` for earliest document start date derivation, 0-document edge case, and first upload date snapping.
- [x] **VER-02**: Update frontend Vitest test suites to verify the minimalist register layout (tenants top, single divider, applicants bottom) and auto-anchored start date behavior in House Settings.
- [x] **VER-03**: Verify all backend (.NET xUnit) and frontend (Vitest) suites achieve 100% pass with zero regressions.
