# Quick Task Summary: UI-Based Tenant Management & Document Reallocation

## Overview
Implemented an intuitive dashboard UI and supporting backend API/database services allowing users to view, add, edit, and delete tenants for any house, configure residency date ranges, and automatically reallocate documents based on strict domain priority rules.

## Core Priority Rules Implemented
1. **Explicit Name Priority**: Documents or pages explicitly containing an expected tenant name strictly remain assigned to that tenant, even if the document's date falls into another tenant's tenure timeline.
2. **Date-Range Fallback**: Unnamed documents (such as utility bills or generic notices) are dynamically reallocated based on the document's `primary_date` matching tenant `[start_date, end_date]`.
3. **Active/Latest Tenant Fallback**: Documents lacking both an explicit tenant name and a primary date fall back to the active/most recent tenant.
4. **Manual Document Override**: Users can manually reassign individual documents to any tenant from the document viewer dropdown (`#viewer-tenant-select`), atomically syncing `documents.tenant_id` and all associated `pages.tenant_id`.
